# INI Weaver

[中文版本](README.zh-CN.md) | English

INI Weaver is a visual INI editor for Red Alert 2 / Yuri's Revenge modders.
Instead of copy-pasting `<section>` snippets by hand in Notepad and wiring
flags across many files, you drag pre-made modules onto an infinite canvas
and draw lines between their linkage points — the editor writes the INI for you.

![Module Links](pic/Module_Links.png)

## What it does

- **Canvas-based editing**: place `<section>` modules and connect their
  linkage points to express references like `Weapon=`, `Projectile=`,
  `Warhead=`. Unconnected linkage points are dropped from the final INI.
- **Module library**: ships with commonly used sections under
  `\Global\Modules`. Build your own library by selecting modules on the
  canvas (Ctrl+C) and pasting them into the library's clipboard template
  after `Data=`. Clipboard-created library modules even preserve the
  relative positions between modules.
- **Reverse linking**: drop a projectile onto a weapon module and the link
  is wired automatically using the right flag — that flag is created on
  demand if missing. Reverse-link rules are declared in `RegisterTypes.json`.
- **Flag dictionary**: `TypeAlt.csv` only needs to declare flags that
  cross category boundaries; other flags inherit their on-canvas behavior
  from the loaded modules (`=yes`/`=no` → boolean toggle, anything else →
  text).
- **Direct SHP/VXL import**: drop a `.shp` or `.vxl` onto the window and a
  new module of the matching type is spawned.
- **VS Code-style dark UI**: Qt6 + QML frameless main window, a minimap for
  navigation, list view, and a settings panel.

## Hotkeys

| Key                        | Action                                |
|:---------------------------|:--------------------------------------|
| F2                         | Toggle display mode (comment / real section name) |
| Ctrl+S                     | Save project                          |
| Ctrl+Shift+S               | Save project as                       |
| Ctrl+O                     | Open project                          |
| Ctrl+E                     | Export INI                            |
| Ctrl+W                     | Close project                         |
| Ctrl+C / Ctrl+V             | Copy / paste modules                  |
| F3                         | Rename section name                   |
| Left-click on canvas        | Select module / enter edit mode       |
| Right-click on canvas       | Module library                        |
| Double-click on canvas      | Module search                         |
| Right-click on module title | Module context menu                   |
| Double-click on a flag      | Edit flag value                       |

## Building

INIWeaver builds with CMake + Qt 6.8.x + QML on Windows.

> The legacy Dear ImGui version (`legacy-imgui\INIBrowser.sln`) is archived
> and no longer compiles. Use the root `INIWeaver.sln`.

```powershell
cd <repo-root>
cmake -S . -B build
.\sync-sln.ps1
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" INIWeaver.sln -p:Configuration=Release -p:Platform=x64 -m -verbosity:minimal
```

Build product: `Release\INIWeaver.exe` at the repository root.

**Re-configuration** (after adding QML files or C++ sources):

```powershell
cmake -S . -B build
.\sync-sln.ps1
```

The root `INIWeaver.sln` is a derived wrapper generated by `sync-sln.ps1`
from `build\INIWeaver.sln`: every `.vcxproj` reference is rewritten with a
`build\` prefix so the sln lives at the repo root while the actual project
files stay in the CMake binary directory. It is git-ignored — regenerate it
after every CMake configure. Intermediate objects, cmake cache, Qt6 generated
code, and import libraries remain under `build\`.

### Runtime

Copy `Release\INIWeaver.exe` into a folder that already has the Qt6 runtime
DLLs (the deployment folder in your distribution). Replacing just the EXE is
enough.

## Project layout

```
INIBrowser/            Qt6 + QML business code (Qt bridge / controllers / QML UI / QtMain.cpp)
INIBrowser/qt/         Qt bridge layer (ProjectController, WorkspaceController, ...)
INIBrowser/ui/         QML UI organized by panels / workspace / dialogs / components
ImGui/                 Dear ImGui sources (still compiled; Qt6 path uses it as a dependency)
legacy-imgui/          archived ImGui-era VS solution + entry, no longer built
libs/                  third-party libraries (glfw, ...)
docs/                  Sphinx documentation source (English + zh_CN translations)
pic/                   screenshots and GIFs referenced by the docs and this README
CMakeLists.txt         CMake source
sync-sln.ps1           regenerates the root INIWeaver.sln from build\INIWeaver.sln
INIWeaver.sln          derived wrapper sln (git-ignored)
Release\               EXE output directory for Release builds (git-ignored)
build\                 CMake binary directory (git-ignored)
```
